# Agent Note：todo 进度跨轮次常驻

Status: implemented

[English](2026-09-12-todo-progress-persists-across-turns.md) | 中文

取代[下一轮次开始时清空 todo 计划条](2026-07-28-todo-plan-clears-on-next-turn.zh.md)，本 Note 反转的正是那条 Note 所记录的理由。

## 问题

`todo_write` 在会话日志中存储完整列表快照，交互式宿主把最新列表渲染为用户看到的进度面板（web 端 TodoPanel 经 `todos` 投影）。[轮次边界清空](2026-07-28-todo-plan-clears-on-next-turn.zh.md)让这个面板成了单个轮次的产物：第 N 轮写入的列表，在第 N+1 轮开始时就没了。该规则假定模型会在每个「接着干」的轮次开头重述完整列表，工具描述也确实这样要求——但一个只规划一次、随后一直干下去的模型并不会重述，面板于是在这个会话余下的时间里一直空着。preset 切换让情况更糟却并非根因：切换本身不开轮次、也不清空任何东西，因此面板活过了切换，却在用户发出的下一条消息上消失。进度面板是用户持续跟踪的持久状态，不是 harness 可以自行退役的按轮次产物。

## 决定

常驻计划就是日志中最近一次 `todo/write`，仅此而已。轮次边界不改变它：`turn/start` 与 `turn/end` 对 `todos` 投影都是空操作，因此只有之后的写入才会推动面板，而一次携带空列表的写入就是显式清空。

### 宿主投影（web）

`dsh-tool-todo` 的 `todos` 投影单元的 `apply` 折叠该规则：对每个 `todo/write` 返回 `event.data.todos`，对其他任何事件（含 `turn/start`）返回同一个 state 引用。该单元以 `stateVersion` 3 注册（原为 2），使按轮次作用域规则折叠出的持久投影缓存行被丢弃，而不是被当成当前值提供。这是同一事件集合之上的客户端运行时投影，因此不涉及 `SESSION_FORMAT_VERSION`，也没有新增、删除或修改任何会话事件。

同一规则的两处其他折叠一并更新：无密钥连接 fixture 的 `backscanTodos`（以及它的 `session/projection` 推送条件——不再在 `turn/start` 时推进），以及 `dsh-tool-subagent-control` 中 `agent_inspect` 的 `foldSession`——它按该投影的生命周期提供 subagent 的常驻列表。

### 面向模型的纪律

进度面板现在是模型自己对工作进展的持续陈述，工具描述说明了什么会推动它：某一步完成的当下就更新该项；计划变化时随时改写完整列表（任务可以退回 `pending`）；整个计划废弃时发送空列表；上下文压缩后用 `todo_read` 取回确切列表。随附的四个 preset（`standard`、`deep-think`、`cordis`、`minimal`）各自以自身文风写了同口径的一句话。原先「在每个接着干的轮次里第一件事就是重述完整列表」的要求已删除：它存在的唯一目的就是抵消那次清空。

## 考虑过的备选方案

- **保留清空并要求每轮重述**——本 Note 所要反转的现行行为。它让正确性取决于模型是否记得一个记账动作，而它的失败模式是进度面板静默变空，而不是一个可见的错误。
- **当所有条目都 `completed` 时自动清空**——自动退役同样会隐藏被放弃或只做了一半的计划，而且它把面板的生命周期变成模型状态标签的函数，而不是模型意图的函数。
- **在 `turn/end` 清空**——用户还在读那条完成计划所对应回答的时候，就把已完成的清单藏起来。
- **在轮次开始时追加空的 `todo/write`**——为显示规则改写日志，并捏造模型从未写出的写入。

## 后果

用户在一个轮次结束时看到的面板，在下一轮开始时、模式切换之后、以及重新打开会话之后都还在。清空完全由模型决定，以一次空写入表达，因此模型从未放弃的计划会一直可见。模型做完了计划却没有清空时，那份计划会留在屏幕上进入下一轮——这被接受，因为面板是用户持久的进度记录、归模型所有，而描述已告诉它计划结束时发送空列表。覆盖：`todos` 投影单元自身的断言、无密钥 fixture 的组装 web 快照，以及 `agent_inspect` 的折叠。
