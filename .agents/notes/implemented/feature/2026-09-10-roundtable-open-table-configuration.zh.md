# Agent Note：圆桌开桌配置——深浅、人员模式与模型

Status: implemented

[English](2026-09-10-roundtable-open-table-configuration.md) | 中文

> AlphaDeck 工单 B（需求 R13）。记录桌面的深浅、人员模式与模型为何从部署配置变成开桌时的选择，以及深究桌的研究工具为何是引擎内的一份固定白名单。

## 问题

圆桌过去只由部署配置驱动：`provider` 与 `model` 来自插件的 cordis 配置；名单是四个内置身份加一个没人能写的 settings 数组；每位发言者每轮恰好发一次请求，没有工具、也没有思考参数。用户无法说「这次深挖一下」，也无法说「这次坐五个人」；而页面文案指向的自定义身份路径（「在系统设置里添加」）在任何已交付界面里都不存在。

## 决策

**桌面由三项选择开启，而这三项就是这张桌的身份。** `open(depth, rosterId, provider, model)` 坐定一张桌子、把三项选择写进 `roundtable` settings 命名空间，并清空正在进行的桌。深浅、名单与模型不是可以中途改动的设置：按一份名单产出的转录无法被重新归属给另一份，所以改它们就是开一张新桌。尚未开桌时 `userMessage` 会用记住的配置静默开桌，因此第一条消息不会因为「没设置」被拒；`reset` 保留配置——清空一张桌不等于关掉它。

**名单是具名有序列表，用户自建的按 id 替换内置那份。** `src/identities.ts` 持有五个内置身份与两份内置名单（`classic`：多头、空头、宏观、主持人；`finance`：再加产业专家）；`src/rosters.ts` 把用户自建名单叠加其上。成员只写内置 id、其余留空时沿用该身份的名称与契约——这正是编辑内置名单代价很低的原因；自己写了就用自己的。编辑 `classic` 会存下一份 `classic` 名单，于是内置那份退居兜底，而不是一个需要打补丁的东西。

**主持人是标记，不是 id。** 旧状态机把 id 字面为 `moderator` 的发言者挪到最后，一旦用户给自己的收尾者起名就会失效。现在排序读 `identity.moderator`，于是成员顺序就是辩论顺序，收尾者由名单自己标记——包括一份谁都没标的名单，它完全按列出的顺序发言。

**深究桌的研究窗口在引擎内有界。** 深究发言者交替发请求与调工具，直到给出答复或被某个上限截断；白名单（`web_search`、`web_fetch`、`read`、`glob`、`grep`）固定在 `src/research.ts`，投放给模型的目录是白名单与本部署实际注册项的交集，白名单外的调用会被点名拒绝，而最后一次请求根本不带工具目录。最后这条性质才是窗口必定以发言结束的原因：上限不可能以「再一次会被拒绝的调用」收尾。上限作用于整个窗口——请求数、墙钟、单条结果字符数——否则一个超大页面就会填满发言者的上下文。

**转录留下结论，不留研究过程。** 深究轮次记录一份来源清单（工具 + 它被指向的对象）与发言者自己的文本；工具原始结果只存在于它研究时的那次请求里。桌面看到查证过什么；它意味着什么，由发言来说。

**名单编辑器与 AI 共用只写元数据这条边界。** `saveRosters` 只携带名称、发言契约、成员顺序与主持人标记——从不携带插件、工具或权限——因此人在页面上编辑的四个字段，就是任何调用方能陈述的全部。

## 考虑过的备选

**把深浅做成逐条消息的设置** —— 否决。「这次深挖」读起来很自然，但桌面的上下文是共享的：两位深究、两位浅谈会产生一份轮次彼此不可比的转录，而引擎的逐轮行为会依赖转录没有记录的状态。

**开桌时设置轮数（「无人值守三轮」）** —— 随需求一并推迟。引擎按设计一条用户消息跑一轮（桌面会停下等待引导），无人值守的轮数需要自己的取消与成本说法。

**按身份分别配模型** —— 本工单否决。需求是开桌时选一个模型，而按席位分路由会在没有明确需求的情况下成倍放大目录界面。

**研究窗口内弹审批** —— 否决。四位发言者 × 数步 × 一轮，会让用户为十几次只读读取点同意；替代方案是干脆不研究，而那正是这个功能本身。安全性质由白名单承担：其中没有任何一项能改变工作区、会话或进程。

**按白名单过滤目录但放行调用** —— 否决。投放一套、执行另一套，正是让模型的失败无法归因的那种不对称；拒绝消息点明白名单，发言者才能自我纠正。

## 后果

圆桌页现在以开桌设置开场，三项选择取自上次开桌，名单编辑器写入了页面帮助文案过去指向一个不存在界面的那个 settings 命名空间。内置集合多了一个产业专家席位与一份五人金融小组名单。一张桌里的每次请求都用开桌时选定的模型，因此部署的 `provider`/`model` 配置成了起步默认值而不是路由本身。深究桌的成本最高是每位发言者 `researchMaxSteps` 次请求再加发言——浅谈一轮的三到十倍——它的转录会列出浅谈不会出现的来源。`roundtable` settings 命名空间改变了形状（`identities` → `rosters` + `last`）；没有任何已交付界面写过它。

## 验证

`packages/skill/roundtable/tests/state-machine.spec.ts` 覆盖了主持人列在首位、名单没有主持人、以及 @点名收窄三种排序。`packages/skill/roundtable/tests/roundtable.spec.ts` 在内存 settings provider 与带闸门的假 LLM 上驱动真实网关：内置名单与成员解析、用户名单替换内置名单、`open` 记住选择并拒绝不存在的名单、第一条消息用记住的配置开桌、按桌路由，以及深究桌按白名单研究、拒绝 shell 调用、带来源发言、把研究失败记为跳过轮次。`packages/skill/roundtable/tests/research.spec.ts` 覆盖窗口本身：它的目录、两种拒绝、含失败前缀的结果封顶、强制无工具的最后一次请求，以及 provider 失败路径。`packages/client/ui-roundtable/tests/roundtable.client.spec.tsx` 渲染开桌设置、断言三项选择确实传给了 `open`、演练名单编辑器的上移与保存载荷，并渲染深究轮次的来源。
