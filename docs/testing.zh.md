# 验证

[English](testing.md) | 中文

本 fork 不带测试套件：没有 spec 或快照语料，没有覆盖率或 lint 门禁，也没有 `test`、`check`、`verify` 类 npm 脚本。禁止重新引入门禁的常设规则见根目录 [AGENTS.md](../AGENTS.md)。改动之所以正确，是因为它被真实输入跑过并被接受，而不是因为某个检查器变绿。

## 改动如何验证

先构建，再手动跑受影响的那条路径。

```sh
pnpm run build
```

`pnpm run build` 同时是唯一的类型检查：`build:lib:host` 会执行 `tsc -b tsconfig.host.json`，类型错误会让构建失败。此后的每一步都是真实运行——`pnpm run dev`、`pnpm dsh --profile headless "…"`，或拥有该行为的命令——然后读取持久结果：会话日志、写出的文件、workspace、渲染出的 UI。agent（智能体）对自己做过什么的总结不构成证据。

## 什么算作证据

- **行覆盖率不是正确性证明。** 它只说明这些行被执行过，不说明功能按交付预期工作。未被执行的代码应当删除，而不是补一个只为碰到它的调用方。
- **验证外部世界，而非自我报告。** 从外部重新读取文件或重新运行命令；对 agent 自身输出做关键词探测会让作弊的 agent 通过。
- **走真实入口路径。** 通过 `dsh` 与交付组合启动，而不是手工挂载 `ctx.plugin(...)`；并且要跑已发布产物——普通 `node` 下的 `lib/*.js`——因为 tsx 会掩盖的失败（结算竞态、模块解析、被吞掉的加载失败）正是在那里暴露。
- **只 mock 开销高或不确定的边界**——LLM（大语言模型）适配器、网络、时钟——下游一切保持真实。手写替身只能证明桥接层在搬运字节，不能证明交付的工具行为符合断言。
- **推理（inference）在这里很便宜。** 无密钥 harness 只能证明底层通路；只有真实模型跑过才能证明 agent 能工作。不要吝惜真实 API 运行，也不要把它们的输出录成 fixture。
- **占用即负责到 teardown。** 端口、临时目录、派生的子进程及其进程树都不与任何东西隔离；成功路径和失败路径都要释放。

## 一次性检查

本仓库没有承载测试的 harness，所以检查就是一次真实运行：一个 `dsh` profile、Web 应用，或一个提交前删掉的临时脚本。这类脚本里的工作区 import 通过 `tsconfig.base.json` 的 `paths` 映射解析到 `src`（[布局](development.zh.md#typescript-project-layout)），绝不会经由包的 `exports` 解析到构建后的 `lib/`——那里的陈旧副本会加载第二份模块单例。
