# @deepseek-ai/dsh-roundtable

[English](README.md) | 中文

## 概述

`dsh-roundtable` 是圆桌宿主能力：它注册 `roundtable` Remote 与 `roundtable` settings 命名空间，并拥有驱动同一份共享转录的房间引擎。开桌时确定三件事——深浅（`shallow`：发言者只准联网搜索，不能读工作区文件；`deep`：本部署注册的全部只读工具都在手边）、坐哪一份具名名单、以及全部请求用哪个模型——桌面按这份配置运行，直到被清空；清空会释放这份配置，于是开桌设置重新可达，下一张桌也就可以配成别的样子。五个内置身份（多头研究员、空头审查员、宏观策略师、产业专家，以及永远收尾的中立主持人）与两份内置名单（经典四人、金融小组）是底座，用户自建名单按 id 叠加其上。纯状态机决定顺序、跳过、打断与 @点名；模型从不决定谁下一个发言。发言者生成期间，引擎把尚未完成的这一轮（正文与思考）发布在房间快照上，页面因此看到它逐字生长，而不必等整轮结束。

## 使用本包

在具备 `ctx.settings`、`ctx.llm` 与 `ctx.sessionQuery` 的组合中挂载本插件（接续桌经 `ctx.sessionQuery` 读取被接续的会话；缺它的组合仍可全新开桌，但接续请求会响亮拒绝）。浏览器页面（`dsh-client-ui-roundtable`）经该 Remote 驱动它；面向模型的读取工具在 `dsh-tool-roundtable`。

### 挂载与配置

```yaml
- name: '@deepseek-ai/dsh-roundtable'
  config:
    provider: deepseek-official
    model: deepseek-flash
    researchMaxSteps: 8
    shallowMaxSteps: 2
    researchMaxMillis: 120000
    researchMaxResultChars: 8000
    backgroundTools:
      - asset_run_bg
    runStalenessS: 3600
```

| 字段 | 默认 | 含义 |
|---|---|---|
| `provider` | `deepseek` | 桌面起步用的 provider 路由；开桌选择会覆盖它。 |
| `model` | `deepseek-flash` | 桌面起步用的模型 id；开桌选择会覆盖它。 |
| `sharedDigestMaxChars` | `8000` | 一位后续深究发言者的开场携带的、前序发言者共享已读材料的字符预算。 |
| `archiveDir` | `<harness 主目录>/roundtables` | 关闭桌的转录（与接续导出）写入的归档根目录。 |
| `researchMaxSteps` | `8` | 一位深究发言者的研究窗口允许的模型请求数，含最后那次强制不调工具的发言。 |
| `shallowMaxSteps` | `2` | 一位浅谈发言者的窗口允许的模型请求数：一次可搜索的请求，随后是强制发言。 |
| `researchMaxMillis` | `120000` | 一位发言者研究窗口的墙钟预算。 |
| `researchMaxResultChars` | `8000` | 单次研究工具结果进入模型的字符数。 |
| `backgroundTools` | `['asset_run_bg']` | 深究窗口除只读工具外还可调用的工具名单。这些是「提交后立即返回」的后台工具；同步变更类工具仍然不可用。 |
| `runStalenessS` | `3600` | 台账里的 run 停留 `running` 超过这么多秒后，回合边界即视为失联。 |

`roundtable` settings 命名空间保存用户自建名单（`rosters`：`{ id, name, members }` 数组，成员为 `{ id, name, prompt, moderator }`）与上一次开桌配置（`last`：`{ depth, rosterId, provider, model }`）。id 与内置名单相同的自建名单会替换内置那份；成员的 `name` 或 `prompt` 留空则沿用该内置身份自己的。存下的 `depth` 必须是 `shallow` 或 `deep`：其他值会让命名空间注册失败，而不是悄悄按浅谈运行。

### 先开桌，再说话

`open(depth, rosterId, provider, model, seed?)` 坐定一张桌子并记住这三项选择；深究桌可传 `seed: { sessionId, title }` 接续一场既有对话（见「接续桌」）。若尚未开桌，`userMessage` 会用记住的配置静默开桌。`archiveList(limit)` 与 `archiveRead(id)` 提供圆桌页侧栏历史列渲染所用的关桌历史；`limit` 传 `undefined` 即取默认 12，且它声明为「必传但可为 undefined」而非可选参数——Remote 调用方按位置传齐每个已声明的参数，少传会在到达宿主之前就被客户端面拒绝。清空桌面会释放这份配置并回到开桌设置，设置里预选的正是上次那三项：

- **静默开局**——永远由用户先发言；桌面不会自行开始。
- **轮内**——发言者按名单顺序依次取得发言权，各发言一次；空回复记为「思考后跳过」。
- **等待引导**——最后一位发言者结束后桌面停止；不会自动进入下一轮。
- **打断**——轮内用户消息会取消当前发言者、并入共享上下文，随后从被打断的发言者继续该轮。该消息会把它已经说出的部分作为一条提示附在自己下方，因此桌子回应的是它能看见的句子。
- **中止**——`interrupt` 取消此刻正在生成的发言者，把桌子交还给用户。它已经流出的发言会被冻结进转录，成为一条「已打断」条目（正文、思考，以及其窗口发起过的工具调用，按发生顺序）：转录条目、落日志的 `roundtable/turn` 与归档都带 `interrupted` 标记，页面把它渲染成视觉降级的一栏；后续发言者不再登场，下一条消息重新开始一轮。
- **@点名**——用户消息中的 @名字 会把下一轮收窄为仅该发言者。
- **后台运行**——深究发言者用后台工具（`asset_run_bg`）提交长任务后继续本轮发言，而不是空等。引擎把本桌提交过的 run 记成打开中房间的一份台账，在每个回合边界读取每条 run 的记录文件，把已完成的结果记成系统条目；提交它的发言者获得一轮补充发言——排在刚结束的发言者之后、其余队列之前——该轮的指令要求先给结论，再说明修正了什么。同一位发言者的多条已完成 run 只占一轮补充发言；超过 `runStalenessS` 仍是 `running`、或记录文件读不出来的 run 记一条「已失联」并出账。轮末才回来的 run 会在用户下一条消息开启下一轮时被消费，因为引擎从不自行开轮。
- **清空**——`reset` 清空房间、释放开桌配置，并让开桌设置重新可达；发言过的桌子会先把转录归档（`archiveDir`，默认 `<harness 主目录>/roundtables`），让结论活过进程生命周期，`dsh-tool-roundtable` 也能把它提供给 agent。改开另一张桌时对旧桌同样归档；空桌不写任何文件，归档写入失败则保持旧桌运行而不是静默丢失。
- **跨重启存活**——每次变更都会把打开中的房间写进 `<archiveDir>/live.json`（临时文件 + rename 的原子写），下一个进程据此恢复：桌面配置、转录、状态机状态与共享已读材料。进程死亡时正在发言的房间会以 `wait-user-guide` 回来，队列为空、没有 partial——当时那位发言者已经不在了——因此用户的下一条消息会开始新的一轮。读不出来或解析不了的 live-room 文件会响亮记日志，进程以无桌状态启动，因为一个损坏文件绝不能挡住宿主启动。

主持人永远收尾：被标为 `moderator` 的成员无论列在名单哪里都最后发言，因此成员顺序是辩论顺序，不会变成争抢谁来做总结。

### 深浅：发言之前能做什么

- **浅谈**——一段有界的窗口，只对准一件工具：发言者可以调用 `web_search`（`SEARCH_TOOLS`），别的都不行，然后发言。它不读网页正文、也不读工作区文件，这正是这一档能快起来的原因。浅谈的步数上限（`shallowMaxSteps`）是这一档的设计，而不是研究截止时间，因此它结束的回合从不标记为截断。
- **深究**——先用本部署注册的只读工具加上配置点名的后台提交工具（`backgroundTools`）跑一段研究窗口，再发言：引擎读取发言者作用域内可见的工具定义，留下声明自己只读（`ToolDefinition.readOnly`）的那些，因此注册了新的只读工具的组合无需在此点名就能让它进入这份目录；后台工具则在配置里点名，因为它们的 `readOnly` 契约不允许它们对进程做的事。深究开场还携带接续简报、下方的共享已读摘要，以及「资产后台运行纪律」。深浅两种模式都以同一条消息开场——整份转录加上「现在轮到你」的指令——因此深究发言者是带着桌面在研究。每段窗口受各自步数上限约束（深究 `researchMaxSteps`、浅谈 `shallowMaxSteps`）、整个窗口受 `researchMaxMillis` 约束、每条工具结果受 `researchMaxResultChars` 约束；最后一次请求不带工具目录，它仍要调的调用也不会被执行，因此窗口必定以一次发言结束。发言会把查证过的东西记为来源清单；被限额截断的那一轮会被标记，页面据此说明这是「按已查到的内容发言」；工具原始结果从不进入转录。窗口回放自己每一轮时带上该轮 route 产出的 reasoning 块——thinking 模式的 route 要求工具调用回合随附 reasoning 内容。
- **发言者思考**——每位发言者的请求走桌面选定的 route，思维链随该 route 的默认档位；发言者产出的思考随它那一轮记录：转录条目、落日志的 `roundtable/turn` 与归档各有一份，页面把它渲染成发言旁可展开的一栏。转录条目与实时 partial 都携带这一轮的 `flow` 时间线——思考、调用、再思考，按发生顺序排列——读者因此看到这一轮被产出的过程；扁平的 `reasoning` 与 `tools` 字段仍是权威记录，`flow` 出现之前写下的转录照旧按它们渲染。思考从不进入共享上下文——后续发言者看到的是发言，不是彼此的草稿。
- **接续桌**——深究桌可以接续一场既有对话：`open` 指名会话，引擎经 `ctx.sessionQuery` 读取它，把可见消息渲染成 `<archiveDir>/seeds/` 下的 markdown 文件，并把文件路径告诉每一位深究发言者。对话从不内联进上下文——每位发言者经窗口的 `read` 工具自己读。浅谈桌传 seed 会被拒绝（没有窗口可读它），读不到的会话让开桌响亮失败，seed 也绝不流入被记住的配置。
- **无 agent 桌的研究工具**——web 部署把根级工具禁用、改由每会话 preset 提供，浏览器开桌因此没有可继承的会话作用域。引擎在首次使用时铸一个自有的只读工具作用域（`agentlessResearch`，默认开），从引擎构造时的原始上下文把只读能力挂进去——Remote 调用会让 gateway 的方法体拿到调用方的影子上下文，而挂在影子上下文之下的插件会沿影子来源的 fiber 链解析注入服务，那条链从未声明过它们——并等挂载落定后再让窗口读工具目录。`tool-fs-search` 声明了必填的 `sampleOverCapGlobResults`（两份内置组合行都设 false），引擎自己的挂载因此显式传它。解析不出任何只读工具的作用域会记一条警告，深究发言者将不查证作答；缺能力的部署同样只是少那件工具并记警告。无 agent 桌的调用直接跑已注册的工具定义本体——注册表的执行流水线把检查点、遥测与会话观察者挂在真实的 Agent 上，而无 agent 的房间没有 Agent，因此这些读取只受工具目录、各项上限与窗口截止时间的约束；有 agent 驱动的房间照常走注册表。发言者以**文本形式**写出的工具调用（DSML 标记）不会被执行、也不会成为发言：窗口内会收到纠正提示，最终发言里残留的标记会被剥除。
- **共享已读**——一位深究发言者窗口里读到的东西归全桌所有：每次成功调用的工具、参数与封顶结果会累积（按工具与精确参数去重）成一份摘要，随后续深究发言者的开场携带，因此没有人重复获取全桌已有的材料。摘要按从旧到新流入 `sharedDigestMaxChars` 的预算；每次调用的完整材料仍在落日志的 `roundtable/turn` 研究记录里。

### 可观察的成功与失败

`roster` 返回全部名单、桌面配置与房间，`room` 返回实时快照（含正在流出、尚未完成的 `partial`），`open` 返回开好的房间、名单不存在或深浅取值非法则抛错，`saveRosters` 保存用户自建名单，`userMessage` 以更新后的房间应答，`interrupt` 中止本轮并以落定后的房间应答——因此它能在 `userMessage` 那一轮还在生成时被调用（Gateway 收到一个 unary 请求就派发一个，而 `userMessage` 在本轮启动后立即返回），`reset` 清空桌面并释放配置。记住的名单已不存在时改用默认名单，房间会先写下一条点名所失名单的提示；记住的 provider 或 model 为空则回落到部署默认。记住选择是尽力而为：只读 settings provider、或拒绝写入的 provider，都不会影响本次开桌，下一张桌仍从上次记住的值开始。发言者请求失败时记录一条点名该失败的系统提示，该轮继续下一位发言者而不是卡住；发言权指向名单外的名字时以系统提示跳过。

发言者生成期间，`room` 携带 `partial`：发言者的 id 与显示名、截至目前从各 delta 折叠出的正文与思考，以及这一轮已经发起过的工具调用——模型刚开始流出某次调用时它就会出现，窗口真正执行后原地更新。它覆盖的是这位发言者的**整轮**而不是在途的那一次请求：深究发言者的研究窗口会发多次请求，每次的正文、思考与调用都累积进同一个 partial（以空行分隔），因此读者能看到整轮思考，而不是眼看它被清空重来。partial 同时携带这一轮按发生顺序排列的 `flow` 时间线（思考与调用交错），页面渲染的就是它；扁平的 `reasoning` 与 `tools` 字段与它并存。它只是实时视图：完成后的那一轮会替换它，partial 本身从不写进转录、归档或 session 日志。`roundtable/turn` 在该轮并入转录的提交点追加一次——完成的轮与被用户中止的那一轮的冻结残篇都一样——因此「模型可见 ⟺ 已落日志」不变。

归档与 live-room 是 `archiveDir` 下的两份持久格式。归档是每张关桌一个 JSON 文件（`src/archive.ts`）；live-room 是每次变更后整份替换的单个 `live.json`（`src/live-room.ts`）。两者都用同一个校验器（`src/parse.ts`）回读转录，也都容忍更早版本写下的桌子所没有的字段：条目上的 `interrupted`、`tools` 与活动时间线 `flow` 都是可选的，因此本次改动之前写下的归档照常读出、照常渲染。

## 理解实现

`RoundtableGateway`（`TypertRemoteService`）持有活动状态：桌面配置、状态机、转录、忙碌标记、正在写的那一轮的实时 partial、轮内到达的待处理用户消息、被 `interrupt` 冻结的发言、等待各自发言者下一次登场的补充发言摘要，以及当前发言者的 abort 控制器。发言过的桌子关闭时经 `src/archive.ts` 落盘转录——这就是 `dsh-tool-roundtable` 回读、页面历史列经 `archiveList`/`archiveRead` 服务的持久目录契约。每次变更还会经 `src/live-room.ts` 安排一次 live-room 落盘；防抖把一次轮询间隔内的变更合并成一次写入，每份快照排在前一次写入之后，服务释放时会把待写内容冲刷掉。接续桌的导出活在 `src/seed.ts`。`src/state-machine.ts` 是纯决策内核——它拥有各阶段（`wait-user-open` / `round` / `wait-user-guide`）、队列、跳过、主持人置末、@点名收窄、后台 run 台账，以及把桌子交还用户的 `interruptRound` 迁移，因此发言顺序是已记录事件的函数，而不是模型输出的函数。`src/pending-runs.ts` 是边界对台账的纯决策：读入解析好的 run 记录后，把已完成的变成系统条目与每位提交者一轮补充发言，保留仍在途的、出账失联的。引擎负责读记录文件，并在每轮开始时与每位发言者退场后各执行一次这套决策。`src/identities.ts` 持有五份发言契约与名单词汇；`src/rosters.ts` 把内置名单与用户自建名单合到一起；`src/research.ts` 是深浅两档共用的有界只读窗口，按各自档位选出工具目录，并在每次请求之间复查调用方的取消标志，使一个吞掉了自身 abort 的工具调用无法再开出下一次请求。引擎按窗口步数发 `ctx.llm.stream` 请求并记录折叠后的回复；provider 失败以终止错误块到达，转为一次跳过。每个请求的流都先经 `mirror`，由它把每个 delta 折进这一轮的实时 partial——跨请求边界把同一轮的更早请求一并带过来，在模型刚流出一次工具调用时就为它开出一行，并把思考与调用按发生顺序追加进 partial 的 `flow` 时间线——再交给窗口折叠，因此页面能看到这一轮生长。`interrupt` 冻结这份 partial、中止控制器、把状态机带着空队列交还用户；被打断的发言者在其驱动循环展开时把这份冻结的发言记录下来，因此读者已经看到的内容绝不会被丢弃。

引擎把它那些模型可见的输入写进驱动本房间的那个 agent 的 session：`roundtable/opened`（三项选择、被坐定的发言契约，以及接续桌所指会话的 id、标题与导出路径）、`roundtable/message`（每条用户消息与房间自己加的提示）、`roundtable/turn`（发言契约、该请求携带的桌面文本、发言内容、发言者的思考、深究窗口读到了什么，以及这一轮按发生顺序排列的 `flow` 时间线）。浏览器驱动的房间没有 agent，也就没有可写的 session。

### 源码地图

- `src/index.ts`——Remote、settings 命名空间、开桌配置与房间引擎。
- `src/state-machine.ts`——纯阶段/队列/跳过/打断状态机、状态携带的后台 run 台账，以及把已完成 run 的发言者排到队首的补充发言插入。
- `src/pending-runs.ts`——回合边界对台账的纯决策：哪些 run 消费成系统条目与补充发言、哪些记为失联、哪些仍在途中。
- `src/identities.ts`——内置发言契约与名单/桌面类型。
- `src/rosters.ts`——内置名单、用户自建名单与成员解析。
- `src/research.ts`——深究发言者的只读研究窗口及其上限。
- `src/seed.ts`——被接续对话的 markdown 导出与其暂存目录。
- `src/archive.ts`——关桌归档：记录形状、原子写入、列出与读取。
- `src/live-room.ts`——打开中的房间的持久副本：记录形状、原子写入、恢复与共享已读预算。
- `src/parse.ts`——两份持久格式共用的校验器：一条转录条目、其工具调用与其活动时间线。

<a id="model-experience"></a>
## 模型体验

### 一次发言者请求

#### 模型看到什么

每位发言者的请求以该身份自己的发言契约作为 `system` 消息，并携带一条 user 消息：到此为止的全部转录（旧在前、新在后），加上「以该身份、按发言契约发言、不要重复身份标签」的指令。发言者的窗口以同一条消息开场，并在之后每次请求（含最后那次强制发言）里都保留它，因此它是带着桌面在查证，回答的也正是被问到的问题；深究窗口的开场还额外携带接续简报与共享已读摘要。

#### Token 影响

每位发言者都要看整份转录，因此一轮的成本是各位发言者上下文之和，而上下文逐轮增长——总 token 数随轮长呈平方级增长。深浅两档都是窗口而非一次请求：浅谈发言者最多追加 `shallowMaxSteps` 次请求，深究最多 `researchMaxSteps` 次；每次工具结果按次封顶。

#### KV Cache 影响

system 消息对每个身份稳定，但每位发言者的 user 消息不同且转录在增长，因此相邻发言者请求只共享 provider 能缓存的前缀；除此之外没有跨发言者复用。

### 被截断的研究窗口

#### 模型看到什么

触到 `researchMaxSteps` 或 `researchMaxMillis` 的深究窗口会被告知「现在就用已掌握的信息发言」，且该请求不带工具目录。发言照常成立；这一轮被标记为截断，页面据此渲染「研究时间到，按已查到的内容发言」。

#### Token 影响

强制发言只在窗口上下文末尾追加一条短指令并结束窗口，因此它是给窗口封顶，而不是延长其成本。

#### KV Cache 影响

该指令追加在工具结果之后，不影响已缓存前缀。

### 跳过与失败

#### 模型看到什么

回复为空文本的发言者被记为「思考后跳过」；provider 失败被记为点名该错误的一条系统提示，研究窗口内的失败也是同一条提示。两条记录都会进入转录，因此对之后的每位发言者可见。

#### Token 影响

各一条短记录；失败的轮次还要付出该请求已经消耗的部分。

#### KV Cache 影响

追加在可复用前缀之后的转录里，因此跳过或失败不会扰动已缓存前缀。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>

- **每个宿主一个房间**——引擎只维护一张活动桌；没有房间注册表，`reset` 清空的就是这张桌。
- **重启后从「等用户」恢复，绝不从半句话继续**——打开中的房间是持久的（转录、阶段、配置、共享已读），但在途的那一轮不是：发言者生成期间进程死亡，回来时是等用户状态、`busy` 为假，当时正在写的发言丢失。这部分控制态按设计不作持久化——abort 控制器、待处理消息与 partial 这些超出桌子自身转录的读数，在一个并未在驱动该请求的进程里没有意义。
- **live-room 副本是尽力而为的**——磁盘拒绝写入时只记日志、房间照常运行；该文件按轮询间隔至多写一次，而不是每来一个流式 delta 就写。
- **开桌会清空正在进行的桌**——深浅、名单与模型就是这张桌的身份，因此改它们不可能保留按另一份名单产出的转录。
- **研究窗口只使用部署声明为只读的工具**——深究目录是所有可见定义中带 `ToolDefinition.readOnly` 的那些；一个从不声明该标记的工具哪怕只读也不会进入目录。
- **流式 partial 只活在进程内**——`partial` 仅在一轮在途时存在，且只在运行中的宿主里；它从不归档、从不落日志。被中止的那一轮是唯一活得比它久的部分：`interrupt` 停下发言者时会把它冻结进转录；随进程一起死掉的 partial 就此消失。
- **浏览器驱动的房间没有归属 agent**——房间通过驱动它的 agent 来决定研究工具的归属范围、并写自己的 session 事件，而目前只有进程内、带 agent 作用域的调用方会提供这个 agent。因此浏览器驱动的房间跑研究工具时是无 agent 的：相对路径按部署的文件系统根解析、agent 作用域的工具策略不生效、也没有任何 session 记录这个房间。要让房间归属某个会话，Remote 上需要一个 agent 身份——`@RemoteScope('agent')` 形式的参数，或与会话绑定的房间；两者都还没有建模。
- **新增的 session 事件尚未进入持久化目录**——`roundtable/opened`、`roundtable/message`、`roundtable/turn` 由本包声明，而 `packages/core/session/src/known-event-types.ts` 是从 `SessionEventMap` 声明生成的。必须先重新生成该目录（`pnpm run gen-persistence-catalog`），本构建才能读回带有这些事件的日志。
- **所有人共用一条路由**——一张桌里的每位发言者都用开桌时选定的模型；没有按身份区分的路由。
- **没有「几轮」设置**——一条用户消息跑一轮；「无人值守连跑三轮」无法表达。
