# @deepseek-ai/dsh-client-ui-roundtable

[English](README.md) | 中文

## 概述

`dsh-client-ui-roundtable` 是圆桌主页（U6/R13）：一个 `settings.section` 行（`roundtable`），以满幅房间呈现——头带（实时阶段、桌面配置、就座名单）之下是撑满剩余高度的共享转录，引导输入框钉在房间底部。没有开桌时，房间主体以居中卡片承载开桌设置（与名单编辑器），且不渲染输入框：开桌是这张卡片自己的动作，桌子开了页面才提供引导输入。深浅、发言顺序、只读研究窗口、思考后跳过、打断与 @点名等全部决策由宿主引擎负责，因此本页只发送开桌三项选择（深究桌另有要接续的对话）、用户消息、轮询房间，并渲染房间报告的状态：发言者生成期间以 200 毫秒的高频轮询读取房间，把引擎流出的未完成发言（正文与思考）当作正在生长的最后一条记录增量渲染，其余时间退到 2 秒。本页打开期间，外壳侧栏以圆桌历史列（`sidebar.section`）替换工作区浏览区：当前这桌固定在最上，其下才是关桌（新的在前），两者在该列可见期间都每 2.5 秒重读一次，因此本次停留期间开桌或关桌都会自己出现在列表里；点一下读归档，再点一下回到进行中的圆桌。

## 使用本包

在 web profile 中、`ui-shell` 与 roundtable Remote 之后挂载该行。它需要 `ctx.slots`、`ctx.locale`，以及已挂载的 `roundtable` 与 `session` Remote 面——后者仅用于读取与会话选择器同一份模型清单。

### 挂载与配置

```yaml
- name: '@deepseek-ai/dsh-client-ui-roundtable'
```

无配置。section id 为 `roundtable`，经 shell 的 `shell.page` 洞满幅呈现——shell 对这个 section 撤掉居中页列，页面铺满主区并自管滚动。

### 页面呈现什么

- **开桌设置**——只要没有已开的桌就显示三项选择（深浅、人员模式、模型），每项都默认取用户上次开桌的选择，另有名单编辑器；除了点「开桌」没有任何必填项。设置是房间的空态：以居中卡片渲染在房间主体里，「开桌」按钮就是开桌的动作——桌子开起来之前页面不渲染输入框。深究桌另有接续对话选择器（先选项目、再选其中一场对话）：引擎会把该对话导出为文件、由发言者自己读取——绝不内联进上下文——前序发言者读到的材料也全桌共享。清空桌面会释放那份配置，因此设置会回来，下一张桌可以配成别的样子。未配置任何 provider 的部署会说明这一点，而不是给一个空下拉。
- **历史列**——`sidebar.section` 条目（`src/client/RoundtableHistory.tsx`），在本页打开期间替换工作区浏览区：只要已有开桌，最上方固定显示当前这桌（名单名、深浅、已记录的发言轮数、开场那条用户消息，以及发言者生成期间的「进行中」徽章），其下是近期关桌（`archiveList`），新的在前，两者在该列可见期间都每 2.5 秒重读一次（标签页重新可见时也立刻补读一次），因此本次停留期间开桌或关桌都会自己出现；选中一条归档即按同一房间布局只读渲染该归档转录（`archiveRead`，信息条、无输入框），回到进行中的圆桌可以点最上面那行，也可以点列表下方那个按钮。没有开桌就没有这一行：此时这一列只有归档列表。
- **新开圆桌**——本页打开时，外壳的主操作按钮显示「新建圆桌」并发出 `shell/new-roundtable`；页面释放进行中的桌（宿主会把说过的桌归档）并回到开桌设置，同时清掉历史列此前选中的归档。
- **阶段条**——当前阶段（等待用户开场、轮内、等待引导）、桌面正在运行的配置、忙碌提示、按序的发言队列、轮次计数，以及带二次确认的重置按钮。
- **名单**——桌面所坐名单的全部席位，内置身份带徽标；持有发言权席位的 chip 会被标记。
- **转录**——按序的每条记录，并按「轮」分组：每条用户消息开启一轮，其后的发言都归在这一轮里，轮与轮之间以更大间距加一条细线分隔。发言者轮次各自渲染成一张带细边框的卡片，因此一串发言读起来是一叠消息、而不是一条连续的文本流；每条记录末尾都有一条底栏，沿用会话页消息底栏的写法：左侧是复制动作（复制该条自己的文字，发言者复制其 Markdown 源码，复用同一套图标切换反馈），右侧对齐显示本条元信息——「已打断」标记、这轮调用了多少次工具、读了多少个来源，以及时间。房间不记录 token 用量与单轮耗时，因此会话页那两枚统计 pill 在这里没有对应物。用户消息自成一块高亮区域（淡色底、左侧强调竖线、加粗标签），而不是又一段发言者文字。记录条目为用户消息、发言者轮次（含「思考后跳过」）与系统提示；用户消息按原文纯文本呈现，发言者轮次的发言则走对话区同一套 Markdown 渲染；带思考过程的发言轮次会在发言上方以可展开的一栏展示思考，栏内按引擎的 `flow` 时间线把思考与工具调用按发生顺序交错渲染（每段思考是紧凑 Markdown，每次调用是一行工具行）；`flow` 出现之前写下的转录则回退为「扁平思考在上、扁平调用清单在下」；深究发言者的轮次把查证过的来源收进一行折叠栏（折叠时只显示数量），展开后每条列出工具与对象，网页来源给出短域名链接而不是整条 URL；研究窗口触到上限的那一轮会带上「按已查到的内容发言」的说明。被用户中途叫停的那一轮——引擎把它已经流出的发言冻结下来而不是丢弃——渲染成视觉降级的一块（文字变淡、左侧虚线、底栏一枚「已打断」chip，末尾一句说明），思考与工具调用都保留，思考一栏与它取代的那条流式记录一样默认展开。正在生成的那一轮排在最后：房间把已折叠的正文、思考与工具调用作为 `partial` 发布——深究发言者一轮会发多次请求，引擎是累积而不是重来，因此这里是整轮——页面把它渲染成一条还在长的记录：发言名旁标「发言中…」，正文末尾有闪烁光标，思考一栏在这一轮默认展开，随内容一起增长；这一轮落定后它被正式记录取代。视图只在读者本来就在底部附近时才跟随最新一条：由滚动位置而不是渲染决定，因此上滚回看的读者不会被下一次轮询拽回底部。
- **工具调用**——深究发言者发言前会查证，这些调用每次一行渲染成紧凑的一行，与会话页工具行同一风格：状态点（调用进行中、已完成、失败，或被叫停时正卡在途中的「已打断」）、动作的本地化名称（`web_search`、`web_fetch`、`read`、`read_image`、`grep`、`glob`；其他工具沿用其线上名）、一行说明它查了什么，以及状态 chip。展开某一行会显示该调用的参数 JSON（最多 2000 字符）等宽块。正在生成的轮次下方、以及已落定或被叫停的记录条目下方，渲染的都是同一套行——调用在模型刚开始流出时就出现，窗口真正执行后原地更新；带 `flow` 时间线的轮次则把每一行放在它发生的那段思考之后。不渲染结果正文；发言者从调用中得出的结论就是它的发言。
- **输入框**——只在有已开桌时渲染（设置卡片与归档只读视图都没有）：一个输入，用于引导一轮或 @点名某个身份；动作按钮在桌面空闲时是「发送」，在发言者生成期间变成「打断」。打断按钮不看草稿是否为空，随时可用：它取消此刻正在生成的发言者，并把它已经说出的部分冻结进转录成为「已打断」条目，因此读者刚看着长出来的内容不会消失；随后桌子留回等待用户的状态，下一条消息重新开始一轮，而不是排在发言者后面。输入框左侧的 `@` 控件在输入框上方展开当前这桌的与会身份列表——就是头带上那几个身份，可用指针点击，也可用方向键走查；选中一位即在光标处写入 `@名字` 并把键盘交还输入框；显示名里带空格的席位改用它的身份 id，因为宿主把一次点名读作一个以空白分隔的 token。Escape、选中一项、或在列表外按下指针都会关闭它。

### 名单编辑器

编辑器经 `saveRosters` 写入名称、发言契约、成员顺序、谁收尾，以及成员的增删；编辑内置名单等于编辑一份按 id 替换它的副本，保存后页面重新拉取名单。「本名单加一位」给正在编辑的这份名单加人，新席位从某个内置身份起步，因此自建名单不会被卡在一个人；另有单独一个控件新建名单。每位成员只发这四个字段——名单属于讨论配置，因此永远触不到插件或权限。

### 可观察的成功与失败

加载失败渲染带重试按钮的错误行；发送失败渲染同一行；`open` 被拒绝时设置留在页面上并给出宿主的原因。只要有一张桌处于开启状态，页面就轮询房间：发言者生成期间每 200 毫秒一次（`partial` 就在这个节奏上生长），其余时间每 2 秒一次；没有开桌时不轮询。历史列在可见期间按自己的 2.5 秒节奏同时重读进行中的房间与归档列表：列表读失败时以失败提示替换列表，房间读失败则只是留着上一次的「当前这桌」那一行——下一个间隔已经在路上。

<a id="understand-the-implementation"></a>
## 理解实现

`RoundtablePage` 持有房间视图、全部名单、记住的桌面配置、模型选项与失败标记；只要桌面开启就轮询房间（发言者生成期间 200 毫秒、其余时间 2 秒），在读者靠近底部时把转录保持在最新一条上，并把扁平的记录列表按「轮」渲染——每条用户消息开启一轮，轮间分隔来自这个分组，而不是记录里的某个字段。跟随滚动由一个 ref 里的标记决定：它由容器自身的 `scroll` 事件更新、在房间更新之后应用，而不是用每次渲染都会滚动的回调 ref——`partial` 每次轮询都在长，渲染驱动的滚动会把上滚的读者拽回去。房间报告的 `partial` 以发言者 id 为 key 渲染成最后一条仍在生长的记录，因此思考一栏每次发轮只挂载一次、不会在轮询之间被反复折叠。工具调用只是房间已有数据之上的呈现：`TurnActivity` 按条目的 `flow` 时间线绘制这一轮的过程（`FlowDisclosure`——紧凑 Markdown 的思考段与 `ToolActivityLine` 工具行按发生顺序排列），对没有时间线的条目或 partial 回退为「扁平思考一栏 + 扁平调用清单」，因此「已打断」条目里冻结的调用、实时轮次里进行中的调用与旧归档读起来一致，展开后显示引擎记录的原始参数 JSON——页面自己从不调用工具、也不去取结果。首屏之后才到达的配置——无论改的是三项里的哪一项——都会被设置面板采纳，直到用户动过控件。`src/client/index.ts` 注册 `ui.roundtable` 字典与 section 行，把每次 Remote 结果解包为页面渲染的值，并把会话模型清单摊平成 `provider/model` 选项。外壳的「新建圆桌」动作以 `shell/new-roundtable` 事件到达页面，由 `src/client/index.ts` 投影成一个 `newTable` 观测源、再被渲染器绑定为页面的 `useNewTable` 席位；反应由页面自己做（清掉归档选中态、`reset`、再把释放后的配置读回来）。

### 源码地图

- `src/client/index.ts`——字典注册、`roundtable` section 行与历史列，以及 `load` / `models` / `open` / `saveRosters` / `room` / `send` / `interrupt` / `reset` / `archiveList` / `archiveRead` 适配器。
- `src/client/RoundtablePage.tsx`——房间：开桌设置（含深究桌接续选择器）、阶段条、名单、转录、思考与工具调用的 `flow` 时间线、「已打断」条目渲染、输入框，以及归档只读视图。
- `src/client/RoundtableHistory.tsx`——侧栏历史列。
- `src/client/history-store.ts`——历史列与页面共享的归档选中态；列表本身的新鲜度归历史列自己管：它按自己的节奏重读归档列表与进行中的房间——房间搭的是列表这一拍，而不是自己另开更快的节奏，因为页面在发言者生成期间本就每 200 毫秒轮询一次房间，而这一行只显示名单、深浅、发言数与忙碌标记——并按 `closedAt` 排序，而不轻信宿主给的顺序。当前这桌那行的名单名取自开桌设置本就要做的那次 `roster` 读取，因此一次请求同时供上房间快照与名单名。
- `src/client/locales.ts`——`ui.roundtable` 字典键。

<a id="model-experience"></a>
## Model Experience

无——页面只渲染房间快照；每次模型请求都由宿主引擎负责，页面从不组装。

#### KV Cache effect

无；本包既不组装也不发送 provider 请求。

## 已知限制与后置工作

<a id="known-limitations-and-deferred-work"></a>

- **单房间**——宿主只维护一张活动桌，本页也只渲染这张桌；没有房间列表或按房间路由。
- **增量显示靠轮询，不是推送**——Remote 是 unary RPC，宿主无法推送；生成期间页面每 200 毫秒读一次房间，因此一个 delta 最多晚一个轮询间隔出现在屏幕上。历史列在可见期间每 2.5 秒重读一次进行中的房间与归档列表，因此一张新开或新关的桌子——以及「进行中」徽章——最多晚这么多出现。
- **房间能扛过宿主重启，在途的那一轮不能**——引擎会持久化打开中的房间（转录、阶段、配置），本页挂载时重新读回，因此重启后的宿主显示的是同一张桌。进程死亡时正在生成的那位发言者回来时是一张等用户的状态、那一轮丢失；页面只渲染房间报告的内容，自己没有任何「重启」专用状态。
- **工具行展示的是调用，不是结果**——房间记录每次调用的工具、参数、一行主题与状态，页面渲染的就是这些；结果正文留在引擎的 session 日志里，页面从不去取。
- **席位的身份 id 在编辑器里固定**——可写的成员字段是显示名、发言契约、顺序与谁收尾；id 只读显示，因此新增席位从某个内置身份起步，「凭空新建一个身份」留给宿主侧去做。
